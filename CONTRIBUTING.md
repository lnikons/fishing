# Правила роботи з репозиторієм

## Гілки

| Гілка | Призначення |
| --- | --- |
| `main` | стабільна версія гри; оновлюється лише з `develop` на релізі |
| `develop` | поточна розробка; сюди зливаються готові задачі |
| `feature/<номер>-<назва>` | одна задача — одна гілка, наприклад `feature/9-cast-rod` |

Назва гілки — латиницею, малими літерами, слова через дефіс. Номер — це номер картки на дошці KanbanFlow.

## Коміти

- Формат повідомлення: `T<номер>: що зроблено`, наприклад `T9: додано анімацію поплавця`.
- Коміти дрібні й часті: одна змістовна зміна — один коміт.
- Не комітити `bin/`, `obj/`, `.vs/` (їх уже виключено в `.gitignore`).

## Робочий цикл задачі

1. Перемістити картку з «Беклогу» у свою колонку WIP (з урахуванням ліміту).
2. Оновити `develop` і створити гілку задачі:
   ```
   git switch develop
   git pull
   git switch -c feature/9-cast-rod
   ```
3. Працювати, комітити, періодично відправляти гілку: `git push -u origin feature/9-cast-rod`.
4. Перед pull request підтягнути свіжий `develop` у свою гілку й переконатися, що проєкт збирається:
   ```
   git fetch
   git merge origin/develop
   ```
5. Створити pull request у `develop`, назва — як у коміту (`T9: ...`), в описі — що зроблено й як перевірити. Картку перемістити в «Виконано».
6. Лев перевіряє зміни (колонка «WIP Тестування»): якщо все гаразд — схвалює й зливає pull request, картка йде в «Готово». Якщо ні — залишає коментар, картка повертається в колонку WIP автора.
7. Після злиття видалити гілку задачі.

## Правила

- Прямих комітів у `main` та `develop` немає — тільки через pull request.
- Свій pull request сам не зливаєш.
- Конфлікти вирішує автор гілки, яка зливається.
- Свої зміни роби у своїй частині рішення: логіка — `Fishing.Core`, форми — `Fishing.App`. Чужі файли змінюй лише за домовленістю.
- Файли `.sln` і `.csproj` змінюються рідко й тільки за потреби: додав проєкт чи пакет — одразу злий це в `develop` і повідом команду.
- Не залишати в `develop` код, що не збирається.
- Перша задача, яка зливається, — № 18 (рішення C#). Решта гілок створюються після неї.
